# 물품코드 스캐너

브라우저에서 카메라·사진의 `4자리-6자리` 영문/숫자 물품코드를 읽고 엑셀의 위치와 연결하는 정적 웹 앱입니다. 빌드 단계나 추가 npm 의존성은 없습니다.

## 실행

```sh
python -m http.server 8080 --bind 127.0.0.1
# 같은 기기에서 http://127.0.0.1:8080/ 접속
```

실제 외부 배포는 HTTPS를 사용하세요. 카메라는 브라우저 권한과 보안 컨텍스트(HTTPS 또는 localhost)가 필요합니다. 헤드리스 환경의 화면 검증만으로 실제 카메라 호환성을 보장하지는 않습니다.

SheetJS와 Tesseract.js 및 OCR 엔진/언어 데이터는 외부에서 로드하므로 최초 접속에는 인터넷이 필요합니다. 사진 픽셀은 브라우저에서 처리합니다. 완전한 오프라인 사용은 아직 지원하지 않습니다.

## 기본 흐름

1. 엑셀을 선택합니다: A열 코드, B열 위치. 같은 코드의 여러 위치는 합쳐집니다.
2. 카메라 또는 사진을 선택하고 코드를 인식합니다.
3. 확인 필요 코드는 이미지의 코드 박스를 눌러 수정합니다. 새 이미지/모드로 이동하면 확인 근거가 사라지므로 먼저 확인하는 것을 권장합니다.
4. 결과에서 위치를 확인합니다. 기록은 이번 접속의 메모리에만 보관되며 새로고침하면 사라집니다. 엑셀과 인식 설정의 자동 저장과는 다릅니다.

`테스트 · 고급`에서는 합성 이미지를 생성하고 원본/보정본과 최적화 결과를 비교합니다. 테스트 결과는 실제 조회 기록에 추가하지 않습니다. 생성 상한은 한 변 4096px, 총 800만 픽셀, 1000개 코드입니다. 임의의 긴 식별자는 정상 물품코드로 잘라내지 않으며, 별도로 붙은 단일 V 체크 접미사만 확인 대상으로 처리합니다.

## 검증

Node.js 26에서 검증했습니다. 추가 설치 없이:

```sh
node --test tests/*.test.cjs
for file in *.js tests/*.cjs; do node --check "$file" || exit 1; done
git diff --check
```

독립 lint/typecheck/build 도구는 구성되어 있지 않습니다. 위 명령은 테스트·구문·공백 검증이며 전용 정적 분석을 대체하지는 않습니다.

### 브라우저 회귀 확인

로컬 서버를 연 상태에서 Chromium/DevTools MCP로:

- 390×844 터치 화면 및 844×390 가로 화면에서 메뉴와 인식 버튼이 도달 가능한지 확인합니다.
- 테스트 이미지는 기본값보다 단순한 조건(4×2cm, 254PPI, 여백 10px, 글자32px, 세로간격15px, 기본 배경·표 숨김)으로 먼저 확인합니다.
- 테스트 자동 최적화 후 보정 화면의 이미지/박스가 최신인지, 실제 결과 기록 수는 증가하지 않는지 확인합니다.
- 과대 크기 입력은 생성 전에 안내로 거부되는지 확인합니다.
- 미확인 실작업 코드가 있는 상태에서 새 이미지/모드 전환을 취소하면 기존 확인 화면이 남아야 합니다. 진행하면 기록에 재촬영 필요 상태가 즉시 표시되어야 합니다.
- 콘솔 오류와 워커 대체 원인을 확인합니다. 보정 워커는 15초 무응답 시 종료 후 CPU로 대체하며 5초 뒤 새 요청에서 재시도합니다. OCR 취소는 진행 중 결과를 폐기하고 완료를 기다리는 방식입니다.

촘촘한 표·흐린 인쇄물의 정확도, 실제 카메라, 장시간 작업과 기기별 GPU는 별도 실기 검증이 필요합니다.
